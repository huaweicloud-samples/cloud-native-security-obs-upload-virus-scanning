# 架构说明

## 总体架构

对象写入私有桶后，关键操作通知把事件投递到通知主题，再由主题触发无服务器函数。
函数读取对象字节，运行已注册的检查规则，并根据判定结果写回对象状态或删除对象。
所有执行记录以结构化日志写入日志服务。

完整档（启用定时复核）：

```
                        ┌────────────────────┐
                        │ 对象写入/定时复核  │
                        │ CTS / SMN 通知链路 │
                        └──────────┬─────────┘
                                   │ ① 事件或定时规则触发
                                   ▼
┌────────────────────────────────────────────────────────────────────┐
│          FunctionGraph 函数（Python 3.9 · 512 MB · 60 s）          │
│          index.handler · 单个 function.zip（仅自有模块）           │
└──────────┬───────────────────────┬───────────────────────┬─────────┘
           │                       │                       │
           ▼                       ▼                       ▼
┌────────────────────┐  ┌────────────────────┐  ┌────────────────────┐
│   ② 读取对象内容   │  │ ③ 写回状态 / 处置  │  │    ④ LTS 日志组    │
│ OBS getObject 读取 │  │ 对象元数据 / 删除  │  │   结构化 JSON 行   │
└────────────────────┘  └────────────────────┘  └────────────────────┘
```

                                   ▼
┌────────────────────────────────────────────────────────────────────┐

│          index.handler · 单个 function.zip（仅自有模块）           │
└──────────┬───────────────────────┬───────────────────────┬─────────┘
           │                       │                       │
           ▼                       ▼                       ▼
┌────────────────────┐  ┌────────────────────┐  ┌────────────────────┐
│   ② 读取对象内容   │  │ ③ 写回状态 / 处置  │  │    ④ LTS 日志组    │
│ OBS getObject 读取 │  │ 对象元数据 / 删除  │  │   结构化 JSON 行   │

> 两档的差异只在发起端：完整档多一个定时触发器用于周期性复核；
> 函数、存储、通知与日志链路完全一致。

## 关键组件

| 组件 | 作用 |
|---|---|
| OBS 私有桶 | 存放待检查对象；函数从中读取内容、写回状态或删除对象 |
| CTS 关键操作通知 | 选择桶内的对象写入操作并投递事件 |
| SMN 主题 | 事件投递通道，同时是函数的触发器来源 |
| FunctionGraph 函数 | `index.handler`，Python 3.9，单个部署包，只依赖运行时内置客户端 |
| IAM 委托 | 授予函数对桶的读写权限，凭据由运行时临时提供 |
| LTS 日志组 / 流 | 保存结构化 JSON 执行日志 |

## 工作流程

1. 对象写入桶，产生关键操作记录。
2. 关键操作通知把记录发往通知主题。
3. 主题触发函数，事件信封为 `record[0].smn.message`（JSON 字符串）。
4. 函数解析桶名与对象键，先写 `in-progress` 状态。
5. 读取对象字节并依次执行已注册的检查规则。
6. 无命中 → 写 `clean` 状态并保留对象；有命中 → 按配置删除对象或写 `quarantined` 状态。
7. 输出结构化日志与调用返回体。

## 事件信封与解析

函数同时兼容三种入口：主题投递的 `record` 信封、直接携带 `cts` 的事件、
以及 `bucket` / `key` 顶层的手动测试事件。解析逻辑集中在 `src/functions/src/events.py`，
业务入口不感知投递通道差异。非写入类操作（例如删除对象）会被跳过，避免递归触发。

## 检查规则与处置状态机

检查能力通过 `register_rule()` 注册，规则签名固定为「接收字节、返回命中说明或空值」。
仓库内置的 `demo-signature` 规则只匹配一段标准测试特征串，用于本地验证命中分支，
**不是恶意代码检测引擎**。接入生产环境时，应把企业内容检测服务注册为规则，
并按需停用内置演示规则。

| 判定 | `preferred_action=delete` | `preferred_action=tag` |
|---|---|---|
| 无规则命中 | 写 `clean`，保留对象 | 写 `clean`，保留对象 |
| 有规则命中 | 删除对象 | 写 `quarantined` 与命中规则列表，保留对象 |

状态通过 OBS 对象自定义元数据写回，键为 `check-status` 与 `check-findings`。
运行期的状态写入不会被部署配置回滚：Terraform 只管理资源定义，不管理对象元数据。

## 安全设计

- 桶为私有访问，不开放匿名读写。
- 函数通过服务委托获得临时凭据，部署包内不含任何长期凭据。
- 函数只处理配置前缀下的对象；前缀为空时处理整个桶，建议按业务目录收敛。
- 日志只记录桶名、对象键、状态、字节数与规则名，不写入对象内容。
- 函数部署包只包含项目自有 Python 模块，不打包第三方库与平台原生扩展。

## 配置对应关系

| 配置项 | 默认值 | 作用 |
|---|---|---|
| `preferred_action` | `delete` | 命中后的处置策略，`delete` 或 `tag` |
| `content_prefix` | 空 | 只处理该前缀下的对象 |
| `enable_timer` | `true` | 是否创建定时复核触发器 |
| `timer_schedule` | `0 0 3 * * ?` | 定时复核的 cron 表达式 |
| `function_memory_size` | `512` | 函数内存（MB） |
| `function_timeout` | `60` | 函数超时（秒） |
| `lts_ttl_in_days` | `7` | 日志保留天数 |

## 轻量验证档拓扑

设置 `enable_timer = false` 后不创建定时触发器，函数仍可由对象写入事件或手动调用触发。
该档资源更少，适合只验证事件驱动链路的场景。
